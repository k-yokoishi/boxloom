Every operation below is available through the Python SDK and through the REST API. Choose an interface once and the whole page follows it; the choice is remembered on your next visit and is carried in the page URL, so a link you share opens on the same interface.

Python examples use the connection configured during [Installation](./installation). REST examples use `BOXLOOM_BASE_URL` and, when authentication is enabled, `BOXLOOM_AUTH_TOKEN`.

<ApiLanguageBar />

## Conventions

Dimensions, blocks, and entities are named with namespaced IDs such as `minecraft:overworld`, `minecraft:stone`, and `minecraft:arrow`. A dimension must be loaded by the running server; a block or entity ID must exist in the server's registries.

Block coordinates are 32-bit integers. Player and entity coordinates are finite doubles. Every operation runs on the Minecraft server thread, so a stalled server surfaces as a timeout rather than a hang.

<ApiVariant lang="python">

Top-level functions share one process-wide client. Call `boxloom.init()` to configure it explicitly, or let the first call configure it from `BOXLOOM_BASE_URL`, `BOXLOOM_AUTH_TOKEN`, and `BOXLOOM_TIMEOUT_SECONDS`.

Operations that act on the world take `dimension` as a keyword argument defaulting to `minecraft:overworld`. Every result is a frozen dataclass, so attributes are read-only.

</ApiVariant>

<ApiVariant lang="rest">

The default listener is `http://127.0.0.1:28886`. Send `Authorization: Bearer <token>` whenever the Fabric server is configured with a token; a non-loopback listener always requires one.

Request bodies must be `application/json` and at most 16 KiB. Unknown body fields and unknown query parameters are rejected rather than ignored. Responses are `application/json`, except the event stream, which is `text/event-stream`.

Unlike the Python SDK, `dimension` is never optional: every world operation requires it explicitly.

</ApiVariant>

## Errors

<ApiVariant lang="python">

Every failure raises a subclass of `boxloom.BoxloomError`.

| Exception | Raised when |
| --- | --- |
| `ApiError` | The server returned an error response. Carries `status`, `code`, and `message`. |
| `ConnectionError` | The boxloom server could not be reached. |
| `ProtocolError` | The response did not match the API contract. |
| `ConfigurationError` | The connection configuration is missing or invalid. |
| `EventCursorExpiredError` | An event stream cursor can no longer be resumed. Subclass of `ApiError`. |
| `EventStreamError` | The server reported a failure after the event stream was open. |

```python
from boxloom import ApiError, set_block

try:
    set_block(0, 100, 0, "minecraft:not_a_block")
except ApiError as error:
    print(error.status, error.code, error.message)
```

</ApiVariant>

<ApiVariant lang="rest">

Every failure returns a JSON body with a stable machine-readable `code` and a human-readable `message`.

```json
{
  "error": {
    "code": "INVALID_BLOCK",
    "message": "Block 'minecraft:not_a_block' does not exist"
  }
}
```

</ApiVariant>

These codes can be returned by any operation. Codes specific to one operation are listed with that operation.

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | A field or query parameter is missing, malformed, or out of range. |
| 401 | `UNAUTHORIZED` | A Bearer token is required but was not supplied. |
| 403 | `FORBIDDEN` | The supplied Bearer token is invalid. |
| 404 | `ROUTE_NOT_FOUND` | No such route. |
| 405 | `METHOD_NOT_ALLOWED` | The route does not accept this request method. |
| 413 | `REQUEST_TOO_LARGE` | The request body exceeds 16 KiB. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | The `Content-Type` is not `application/json`. |
| 500 | `INTERNAL_ERROR` | The server could not complete the request. |
| 503 | `WORLD_NOT_LOADED` | No Minecraft world is currently loaded. |
| 504 | `TIMEOUT` | The Minecraft server thread did not respond before the deadline. |

## `say`

Broadcast a system message to every connected player, and report how many players received it.

<ApiVariant lang="python">

```python
say(message: str) -> SayResult
```

**Parameters**

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `message` | `str` | required | The text to broadcast. Non-blank, at most 256 characters. |

**Returns** — `SayResult`

| Attribute | Type | Description |
| --- | --- | --- |
| `message` | `str` | The message as broadcast. |
| `recipients` | `int` | Number of players that received it. |

**Example**

```python
from boxloom import say

result = say("Hello from boxloom!")
print(result.recipients)
```

</ApiVariant>

<ApiVariant lang="rest">

<ApiEndpoint method="POST" path="/v1/chat/messages" />

**Request body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `message` | string | yes | The text to broadcast. Non-blank, at most 256 characters. |

**Response** — `200 application/json`

| Field | Type | Description |
| --- | --- | --- |
| `message` | string | The message as broadcast. |
| `recipients` | integer | Number of players that received it. |

**Example**

```bash
curl --fail-with-body \
  -X POST \
  -H "Authorization: Bearer $BOXLOOM_AUTH_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"message":"Hello from boxloom!"}' \
  "$BOXLOOM_BASE_URL/v1/chat/messages"
```

```json
{ "message": "Hello from boxloom!", "recipients": 2 }
```

</ApiVariant>

## `teleport_player`

Teleport a connected player to absolute coordinates. Omitted dimension and look direction values are preserved.

<ApiVariant lang="python">

```python
teleport_player(
    username: str,
    x: float,
    y: float,
    z: float,
    *,
    dimension: Optional[str] = None,
    yaw: Optional[float] = None,
    pitch: Optional[float] = None,
) -> PlayerPosition
```

**Parameters**

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `username` | `str` | required | 3–16 characters from `A-Z`, `a-z`, `0-9`, and `_`. |
| `x`, `y`, `z` | `float` | required | Absolute destination. Finite, and inside Minecraft's spawnable bounds. |
| `dimension` | `Optional[str]` | `None` | Destination dimension. `None` keeps the player's current dimension. |
| `yaw` | `Optional[float]` | `None` | Horizontal rotation in degrees, wrapped into `[-180, 180)`. `None` keeps the current yaw. |
| `pitch` | `Optional[float]` | `None` | Vertical rotation in degrees, wrapped into `[-180, 180)`. `None` keeps the current pitch. |

**Returns** — `PlayerPosition` describing the player after the teleport, with the same attributes as [`get_player_position`](#get_player_position).

**Example**

```python
from boxloom import teleport_player

position = teleport_player("Steve", 100, 64, -20)
print(position)
```

</ApiVariant>

<ApiVariant lang="rest">

<ApiEndpoint method="POST" path="/v1/players/{username}/teleport" />

**Path parameters**

| Name | Type | Description |
| --- | --- | --- |
| `username` | string | 3–16 characters from `A-Z`, `a-z`, `0-9`, and `_`. |

**Request body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `x`, `y`, `z` | number | yes | Absolute destination. Finite, and inside Minecraft's spawnable bounds. |
| `dimension` | string | no | Destination dimension. Omit to keep the player's current dimension. |
| `yaw` | number | no | Horizontal rotation in degrees, wrapped into `[-180, 180)`. Omit to keep the current yaw. |
| `pitch` | number | no | Vertical rotation in degrees, wrapped into `[-180, 180)`. Omit to keep the current pitch. |

**Response** — `200 application/json`, the player's position after the teleport, with the same fields as [`get_player_position`](#get_player_position).

**Example**

```bash
curl --fail-with-body \
  -X POST \
  -H "Authorization: Bearer $BOXLOOM_AUTH_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"x":100,"y":64,"z":-20}' \
  "$BOXLOOM_BASE_URL/v1/players/Steve/teleport"
```

</ApiVariant>

**Errors**

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `INVALID_DIMENSION` | The dimension is not a valid namespaced ID. |
| 400 | `INVALID_POSITION` | The destination is outside Minecraft's spawnable bounds. |
| 404 | `PLAYER_NOT_CONNECTED` | No connected player has that username. |
| 404 | `DIMENSION_NOT_FOUND` | The destination dimension is not loaded. |
| 409 | `TELEPORT_FAILED` | Minecraft refused the teleport. |


## `summon`

Summon one entity in a loaded dimension, optionally configured with NBT data.

Supplying NBT skips Minecraft's natural spawn finalization, so equipment, variants, and similar randomized traits are not applied. Omit it to get an entity equivalent to a command-summoned one.

<ApiVariant lang="python">

```python
summon(
    entity: str,
    x: float,
    y: float,
    z: float,
    *,
    nbt: Optional[Dict[str, Any]] = None,
    dimension: str = "minecraft:overworld",
) -> SummonResult
```

**Parameters**

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `entity` | `str` | required | Namespaced ID of a registered, summonable entity type. |
| `x`, `y`, `z` | `float` | required | Spawn position. Finite, and inside Minecraft's spawnable bounds. |
| `nbt` | `Optional[Dict[str, Any]]` | `None` | Entity NBT, nested at most 128 levels deep. The `id` key is always overwritten with `entity`. |
| `dimension` | `str` | `"minecraft:overworld"` | Namespaced ID of a loaded dimension. |

`nbt` values convert as follows: `int` becomes an int tag, or a long tag when outside the 32-bit range; `float` becomes a double tag; `bool` becomes a byte tag; `str` becomes a string tag; `dict` and `list` nest. `None` is rejected.

**Returns** — `SummonResult`

| Attribute | Type | Description |
| --- | --- | --- |
| `uuid` | `str` | UUID of the summoned entity. |
| `entity` | `str` | Resolved namespaced entity type ID. |
| `dimension` | `str` | Resolved namespaced dimension ID. |
| `x`, `y`, `z` | `float` | Position of the entity after spawning. |

**Example**

```python
from boxloom import summon

entity = summon(
    "minecraft:arrow",
    0,
    100,
    0,
    nbt={"Motion": [0.0, -1.5, 0.0]},
)
print(entity.uuid)
```

</ApiVariant>

<ApiVariant lang="rest">

<ApiEndpoint method="POST" path="/v1/world/entities" />

**Request body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `dimension` | string | yes | Namespaced ID of a loaded dimension. |
| `entity` | string | yes | Namespaced ID of a registered, summonable entity type. |
| `x`, `y`, `z` | number | yes | Spawn position. Finite, and inside Minecraft's spawnable bounds. |
| `nbt` | object | no | Entity NBT, nested at most 128 levels deep. The `id` key is always overwritten with `entity`. |

`nbt` values convert as follows: a JSON integer becomes an int tag, or a long tag when outside the 32-bit range; a floating-point value becomes a double tag; a boolean becomes a byte tag; a string becomes a string tag; objects and arrays nest. `null` is rejected.

## `watch_chat`

Listen for player chat messages as one long-lived stream. With no cursor the stream starts at the current live position and does not replay chat that predates the connection. Reconnecting with the ID of the last event you processed replays retained events strictly after it; the server keeps the most recent 1,024 chat events, and cursors do not survive a Minecraft server restart.

<ApiVariant lang="python">

```python
watch_chat(
    *,
    last_event_id: Optional[str] = None,
    reconnect: bool = True,
) -> ChatEventStream
```

**Parameters**

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `last_event_id` | `Optional[str]` | `None` | Resume strictly after this event ID. `None` starts at the live position. |
| `reconnect` | `bool` | `True` | Whether to reconnect automatically from the last received event when the connection drops. |

**Returns** — `ChatEventStream`, an iterator of `ChatEvent` that is also a context manager.

| Member | Type | Description |
| --- | --- | --- |
| `__iter__` / `__next__` | `ChatEvent` | Blocks until the next chat message arrives. |
| `last_event_id` | `Optional[str]` | ID of the most recent event received, for resuming later. |
| `close()` | `None` | Closes the underlying connection. |

Each `ChatEvent` carries:

| Attribute | Type | Description |
| --- | --- | --- |
| `id` | `str` | Opaque event ID. Use it as the next `last_event_id`. |
| `timestamp` | `str` | UTC ISO-8601 instant. |
| `message` | `str` | The chat message. |
| `player` | `Player` | The sender, with `username` and `uuid`. |

**Example**

```python
from boxloom import watch_chat

with watch_chat() as events:
    for event in events:
        print(f"<{event.player.username}> {event.message}")
```

</ApiVariant>

<ApiVariant lang="rest">

<ApiEndpoint method="GET" path="/v1/events" />

**Request headers**

| Name | Required | Description |
| --- | --- | --- |
| `Accept` | yes | Must allow `text/event-stream`. |
| `Last-Event-ID` | no | Resume strictly after this event ID. Omit to start at the live position. |

**Response** — `200 text/event-stream`

The stream opens with `retry: 1000`, sends comment heartbeats while idle, and emits these named events.

| Event | `data` fields | Meaning |
| --- | --- | --- |
| `stream.ready` | `type`, `cursor` | The stream is open at the given cursor. |
| `chat.message` | `type`, `id`, `timestamp`, `message`, `player.username`, `player.uuid` | A player chat message. Its `id` equals the SSE `id`. |
| `stream.reset` | `type`, `code`, `message` | The cursor became unusable; the response ends after this event. |
| `error` | `type`, `code`, `message` | An unrecoverable stream failure; the response ends. |

Event IDs are opaque and must not be parsed. Use them for deduplication when your processing and cursor persistence are not atomic.
